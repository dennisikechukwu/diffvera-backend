1. WHAT IS SPRING AI & WHY DOES IT EXIST?
--------------------------------------------------------------------------------
In the early days of Spring Boot:
- To access SQL databases, you had to write raw JDBC sockets, manage connections,
  and write manual SQL strings with ResultSet iterations.
- Spring introduced Spring Data (JpaRepository) to abstract away all that boilerplate
  into clean, portable, type-safe Java interfaces.

Spring AI applies the EXACT SAME PHILOSOPHY to Artificial Intelligence & LLMs:
- Instead of manually crafting raw JSON HTTP maps, handling REST headers, dealing
  with curl endpoints, and manually parsing JSON strings with ObjectMapper,
- Spring AI provides a unified, portable, high-level Java abstraction layer across
  ALL AI providers (Google Gemini, OpenAI GPT, Anthropic Claude, Ollama, Bedrock).

With Spring AI, your business logic stays 100% portable. If tomorrow you switch
from Google Gemini to Anthropic Claude or a local Ollama model, you don't change
a single line of your Java code—you only update one line in application.yaml!


================================================================================
2. THE 5 CORE BUILDING BLOCKS OF SPRING AI
================================================================================

--------------------------------------------------------------------------------
A. ChatModel (The Core Engine)
--------------------------------------------------------------------------------
ChatModel is the low-level Spring interface that encapsulates model communication.
Every provider implements this interface:
- OpenAiChatModel
- VertexAiGeminiChatModel / OllamaChatModel / AnthropicChatModel

You rarely call ChatModel directly. Instead, you use the fluent ChatClient.

--------------------------------------------------------------------------------
B. ChatClient (The Modern Fluent API)
--------------------------------------------------------------------------------
Introduced in Spring AI 1.0, ChatClient is inspired by Spring's RestClient and
WebClient. It is the primary tool you will use daily.

It allows you to fluently construct prompts, inject system instructions, pass
runtime parameters, call the model, and automatically deserialize responses.

Example:
```java
@Service
public class CodeReviewService {

    private final ChatClient chatClient;

    public CodeReviewService(ChatClient.Builder chatClientBuilder) {
        this.chatClient = chatClientBuilder
            .defaultSystem("You are Diffvera's Principal Software Architect.")
            .build();
    }

    public String reviewCode(String diff) {
        return chatClient.prompt()
            .user(u -> u.text("Please review this diff:\n{diff}").param("diff", diff))
            .call()
            .content(); // returns the plain string response
    }
}
```

--------------------------------------------------------------------------------
C. Structured Outputs: BeanOutputConverter & .entity()
--------------------------------------------------------------------------------
The single biggest pain point in LLM development is getting typed, structured JSON
back into your Java application without hallucinated formats or JSON parsing errors.

Spring AI solves this natively with Structured Outputs:
When you call `.entity(MyClass.class)`, Spring AI:
1. Uses reflection on your Java class to generate the JSON Schema.
2. Injects instructions into the prompt telling the LLM the exact schema to follow.
3. Automatically parses the LLM's JSON response directly into your Java object!

Example:
```java
public record FindingDto(
    String category,
    String severity,
    String title,
    String explanation,
    int lineStart
) {}

public record ReviewResponse(List<FindingDto> findings) {}

// In your service:
ReviewResponse response = chatClient.prompt()
    .user(diff)
    .call()
    .entity(ReviewResponse.class); // <-- Directly returns typed Java Record!
```
Notice: NO ObjectMapper.readValue(), NO string substring stripping, NO manual JSON parsing!

--------------------------------------------------------------------------------
D. Prompt & PromptTemplate (Dynamic Parameterization)
--------------------------------------------------------------------------------
Instead of ugly Java StringBuilder concatenation:
`sb.append("Repo: " + repoName + " Rules: " + rules);`

Spring AI provides `PromptTemplate`:
```java
PromptTemplate template = new PromptTemplate("""
    ### Pull Request Context
    Repository: {repo}
    PR Title: {title}
    
    ### Active Architecture Rules
    {rules}
    
    ### Changed Files & Diffs
    {diff}
    """);

Prompt prompt = template.create(Map.of(
    "repo", repository.getFullName(),
    "title", pr.getTitle(),
    "rules", formattedRules,
    "diff", diffContent
));
```

--------------------------------------------------------------------------------
E. Message Hierarchy (System vs User vs Assistant)
--------------------------------------------------------------------------------
Spring AI defines a clean message hierarchy:
- `SystemMessage`: Directives and persona guidelines for the model (e.g. "You are an architect").
- `UserMessage`: The actual input/question from the user or developer (the code diff).
- `AssistantMessage`: Prior responses from the AI (used in multi-turn chat memory).

3. SIDE-BY-SIDE COMPARISON: RAW HTTP vs SPRING AI
================================================================================

BEFORE (Raw RestClient HTTP Mechanics):
----------------------------------------
```java
// 1. Manually build prompt string
StringBuilder sb = new StringBuilder();
sb.append("You are an architect...\n");
sb.append("Diff:\n").append(diff);

// 2. Manually construct raw provider JSON map
Map<String, Object> requestBody = Map.of(
    "contents", List.of(Map.of("parts", List.of(Map.of("text", sb.toString())))),
    "generationConfig", Map.of("responseMimeType", "application/json")
);

// 3. Manually call HTTP URL with API key in query string
String rawJson = restClient.post()
    .uri("https://generativelanguage.googleapis.com/v1beta/models/gemini-flash-latest:generateContent?key=" + apiKey)
    .body(requestBody)
    .retrieve()
    .body(String.class);

// 4. Manually strip markdown fences (```json)
String cleaned = rawJson.replace("```json", "").replace("```", "").trim();

// 5. Manually deserialize with ObjectMapper
GeminiReviewResponse response = objectMapper.readValue(cleaned, GeminiReviewResponse.class);
```

AFTER (Idiomatic Spring AI):
-----------------------------
```java
// Everything above reduces to this clean, declarative, type-safe block:
GeminiReviewResponse response = chatClient.prompt()
    .system("You are Diffvera's Principal Software Architect.")
    .user(userPrompt)
    .call()
    .entity(GeminiReviewResponse.class);
```

4. ADVANCED SPRING AI FEATURES TO EXPLORE NEXT
================================================================================

1. Function Calling & Tools (@Tool annotation):
   - You can annotate any Spring bean method with `@Tool`:
     ```java
     @Tool(description = "Look up existing architecture rules for a repository")
     public List<Rule> getRulesForRepo(String repoName) { ... }
     ```
   - When the LLM decides it needs repository rules, Spring AI automatically calls
     your Java method and passes the result back to the model!

2. Retrieval Augmented Generation (RAG) & Vector Stores:
   - Spring AI includes built-in integrations with `PgVector` (PostgreSQL vector extension).
   - You can chunk entire codebases and documentation (.md files) into embeddings
     and let Spring AI automatically retrieve relevant architecture guidelines
     based on semantic similarity.

3. Streaming Responses:
   - For real-time typewriter UI effects on the frontend, Spring AI supports Reactive Streams:
     ```java
     Flux<String> stream = chatClient.prompt()
         .user(diff)
         .stream()
         .content();
     ```

4. Advisors (Interceptors):
   - Intercept calls to log token usage, track latency, or add chat history:
     ```java
     chatClientBuilder
         .defaultAdvisors(new SimpleLoggerAdvisor())
         .build();
     ```

5. SUMMARY & KEY TAKEAWAYS
================================================================================
- Spring AI brings the classic Spring principles (Inversion of Control, Portability,
  and Declarative Templates) to the Generative AI ecosystem.
- `ChatClient` is your primary entrypoint.
- `.entity(YourDto.class)` replaces all manual JSON serialization code.
- By structuring Diffvera around these clean abstractions, your backend is ready
  to support Gemini, OpenAI, Claude, or local open-source models with zero rewrites.
